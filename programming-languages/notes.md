<details>
<summary><strong>프로그래밍 언어를 선택하는 것은 일에 맞는 도구로 고르기</strong></summary>


1. Python
    - 최적의 용도: 데이터 사이언스, 인공지능(AI), 머신러닝, 자동화.
    - 왜: 읽기 쉽기로 유명해요(거의 영어처럼요) 그리고 수학이나 데이터 관련 모든 것에 대한 방대한 라이브러리를 가지고 있어요.
2. JavaScript
- 최적의 용도: 웹 개발(프론트엔드와 백엔드).
- 왜: 이것이 웹의 언어예요. 인터랙티브한 웹사이트나 웹 앱을 만들고 싶다면, 이건 필수예요. Node.js를 사용하면 서버를 실행하는 데도 쓸 수 있어요.
1. Java
    - 최적의 용도: 엔터프라이즈 소프트웨어, 안드로이드 앱, 대규모 시스템.
    - 왜: "한 번 작성하고 어디서나 실행"이에요. 대부분의 대형 은행과 거대 기업들이 안정성과 보안성 때문에 Java에 의존해요.
2. Swift / Kotlin
    - 최적의 용도: 모바일 앱.
    - 왜: iPhone(iOS) 전용으로 만들고 싶다면 Swift를, 안드로이드를 위해선 Kotlin을 사용하세요. 이들은 네이티브 모바일 성능의 현대적 표준이에요.
3. C++ / Rust
    - 최적의 용도: 게임 개발, 운영 체제, 고성능 도구.
    - 왜: 이들은 "저수준" 언어예요. 컴퓨터 하드웨어에 대한 많은 제어를 제공해서 Unreal Engine 같은 것이나 브라우저를 만드는 데 완벽해요.
4. SQL
    - 최적의 용도: 데이터베이스 관리.
    - 왜: 앱을 만드는 데는 아니지만, 데이터베이스와 소통하는 데 써요. 어떤 언어를 선택하든, 데이터를 다루기 위해 SQL이 필요할 거예요.

<details>
<summary><strong>어떤 Java 컬렉션을 사용해야 할까요?</strong></summary>

• 리스트가 필요하다면? 거의 항상 ArrayList.  
• 큐나 스택이 필요하다면? ArrayDeque. Stack이나 LinkedList는 사용하지 마세요.  
• 고유한 항목이 필요하다면? HashSet.  
• 고유하고 삽입 순서대로 유지해야 한다면? LinkedHashSet.  
• 고유하고 정렬되어야 한다면? TreeSet.  
• 항상 가장 작은 또는 가장 큰 항목이 필요하다면? PriorityQueue.  
• 열거형 키가 필요하다면? EnumMap.  
• 읽기 작업이 많고 쓰기 작업이 매우 적으며, 여러 스레드가 사용된다면? CopyOnWriteArrayList.  
• 여러 스레드에서 공유되는 맵이 필요하다면? ConcurrentHashMap.

</details>

<details>
<summary><strong>Java는 사태에 늦게 도착하는 언어입니다. 제가 증명해 보이죠</strong></summary>

람다, 레코드, 가상 스레드, 제네릭. 많은 다른 언어들이 훨씬 전에 이미 가지고 있었죠.

이제 여러분은 이렇게 생각할 수 있겠네요:

- 엘더, 자바를 까는 거예요?
- 전혀요. 제게 이는 자바의 큰 장점 중 하나예요.

왜 그런지 말씀드리기 전에, 늦게 도착하는 데 전문가인 회사를 떠올려 보세요: 애플. 애플은 태블릿을 최초로 출시한 회사가 아니었고, 아이폰 같은 스마트폰이나 아이팟도 아니었어요. 항상 늦게 도착했죠. 그리고 늦게 도착하는 장점은 뭘까요? 다른 사람들이 저지른 실수를 피할 수 있다는 거예요.

제 절친한 친구 한 명이 말하길, 자바는 항상 프로덕션 언어였다고 해요.

- 그래요, 하지만 모든 언어가 프로덕션 언어잖아요.
- 맞아요, 모든 언어는 프로덕션에 배포하기 위해 만들어지죠. 하지만 모든 생태계가 무언가를 출시하기 전에 프로덕션을 먼저 바라보는 문화를 가진 건 아니에요. 자바에서는 그게 항상 최우선 과제였어요.

실제적인 결과는? 람다, 레코드, 가상 스레드, 제네릭, 그리고 수많은 다른 기능들이 프로덕션에서 버그 없이 들어갔다는 거예요. "와, 레코드가 구현을 잘못해서 프로덕션에서 터졌어" 같은 이야기는 찾기 어려울 거예요.

저는 27년 동안 이 분야에 있었고, 자바가 다른 생태계보다 먼저 무언가를 출시하기 위해 서두르는 일은 절대 없을 거라고 생각해요. 그리고 제게 이는 커리어 교훈이기도 해요. 정말로 무언가를 최초로 하기 위해 서둘러야 할까요? 잘 모르겠어요. 시장에서 30년 이상 된 언어를 보면서도 여전히 다른 어떤 언어보다 진화하고 있는 걸 보니, 그들은 자신이 하는 일을 잘 알고 있다는 생각이 들어요.

</details>
